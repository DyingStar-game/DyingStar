# 0026. Link shared materials by name, generate them from material.json, and check them on every pull request

- **Status:** Accepted
- **Date:** 2026-08-29 (the library) · **Recorded:** 2026-10-05 · **Updated:** —
- **Deciders:** WarpZone
- **Evidence:** 30b12c8e, fe7dc95c, #358 (menu entry and pull-request check)

## Context

Models come from Blender and share materials (concrete, metal, corundum…) whose textures must exist
once, not inside every model. Matching glTF materials by surface index broke silently when a slot was
added or reordered. Godot's own guess of which texture carries roughness wired its limiter onto the
occlusion and height maps. The library's Godot resources had to be regenerated by hand after each
change to a manifest, and nothing noticed when it was forgotten.

## Decision

- A shared material is named `mat_<…>` in Blender. Models using it are exported as glTF with
  **Materials: Export** and **Images: None**. The link to the library is the material's **name**,
  never a surface index.
- `assets/_universe/_shared/materials/<id>/material.json` is the source of truth; the folder name is
  its `id`. The `<id>.tres` beside it and the roughness import settings of its maps are generated from
  it (`SharedMaterialBuilder`), never edited by hand. Roughness is pinned from the manifest, never
  detected.
- `post_import_shared_materials.gd` is the project's default scene import script (`project.godot`,
  `[importer_defaults]`): at every model import it puts the library resource on each `mat_*` surface.
- After adding or changing a manifest: **DyingStar ▸ Rebuild shared materials** regenerates the
  library and reimports the models imported before one of their materials existed.
- Every pull request checks that the library matches its manifests, property by property.

## Consequences

- A model imported before its material was published keeps the glTF's own material until it is
  reimported: the rebuild finds and reimports it.
- Generation stays out of the import pipeline: a glTF without images has nothing to build a material
  from, and writing into `res://` mid-import starts a filesystem rescan.
- A change must not hand-edit a generated `.tres`, export a model using shared materials with its
  images embedded, rename a material in Blender without its folder and `id`, match materials by
  surface index, or set a library map's roughness mode back to Detect.

## Rejected alternatives

- Textures embedded in each glTF: every model carries its own copy of every map.
- Matching by surface index: an index is a slot position, which shifts when a slot is added, removed
  or reordered.
- Letting Godot detect roughness maps: it wired the limiter onto ao and height.
- A CI bot that regenerates and commits, as for the credits: it needs a full Godot import for that
  alone. A check names what to run instead.
- Comparing the `.tres` text: it can differ between systems for the same values.

## In the code

- `addons/dyingstar/shared_material_builder.gd`: generation, and the compare-only check
- `addons/dyingstar/shared_material_resolver.gd`: name to resource, linking, unlinked surfaces
- `addons/dyingstar/post_import_shared_materials.gd`: the import script
- `addons/dyingstar/shared_material_rebuild.gd`: the menu entry's work
- `assets/_universe/_shared/materials/`: the library

## Enforced by

- `test/unit/test_shared_material_library.gd`, run as a blocking step of `godot-tests.yml`.
